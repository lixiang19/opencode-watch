## 关键问题

1. 项目列表从哪里来？答案：优先从 `session.list()` 的 `directory` 字段聚合出现有项目，确保“接续对话”目标优先成立。
2. 前端是否直接连接 `opencode serve`？答案：是，前端直连，不增加 Node bridge。
3. 如何保证启动足够简单？答案：在当前目录内提供单条脚本同时启动前端和 `opencode serve`。
4. 消息渲染范围是什么？答案：仅保留 `text` part，忽略 tool、reasoning、file、permission、diff、sub-agent 细节。
5. 如何为指定项目新建会话？答案：创建 session 时显式传 `directory`，不依赖复杂项目管理层。

## 已做决策

| Decision                                   | Rationale                                                      |
| ------------------------------------------ | -------------------------------------------------------------- |
| 直接在当前任务目录内落地实现             | 用户已经明确要求继续开发并交付完整可运行项目                 |
| 技术栈仍建议使用 Vue 3 + TypeScript + Vite | 与参考项目思路一致，但代码必须从零编写，不做任何复用或引入     |
| 前端直接连接 `opencode serve`              | 用户明确要求继续精简架构，不增加中间服务层                     |
| 启动方式统一为一条命令                     | 交付时要尽可能低摩擦，避免前后端分开手动启动                   |
| UI 采用单列移动端布局                      | 手机优先，避免桌面版复杂分栏和重组件开销                       |
| 项目列表按 session 的 `directory` 聚合     | 先解决“接续本机历史对话”这个核心目标，避免依赖不稳定接口       |
