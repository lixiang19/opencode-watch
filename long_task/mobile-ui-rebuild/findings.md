# 发现与决策

## 需求
- 彻底重构前端界面
- 增加路由
- 无需兼容 PC
- 只在手机上使用
- 信息流风格优先

## 研究发现
- 当前项目是 Vue 3 + TypeScript + Vite + Tailwind CSS + shadcn-vue 风格基础组件。
- 当前所有视图集中在 `src/App.vue`，没有路由系统。
- 业务逻辑主要集中在 `src/composables/useOpencodeApp.ts`，适合继续复用。
- `src/components/chat/MessageBubble.vue` 与基础 UI 组件都比较轻，适合顺带一起重做视觉。
- 当前仓库工作区已有较大未提交变更，表现为原 `long_task/opencode-mobile-web-chat/` 下文件删除、项目根目录下文件新增，需要避免覆盖用户已有改动。
- 引入 `vue-router` 后，`App.vue` 可以只负责应用状态初始化和 provide，页面结构转由路由承载。
- 构建验证通过，说明路由、页面拆分和样式重写在当前代码基线上可工作。

## 技术决策
| 决策 | 依据 |
|----------|-----------|
| 新增 `vue-router` 并用 3 个主路由承载首页、聊天页、设置页 | 最符合“只在手机上使用”的信息分层 |
| 使用共享应用状态实例替代每页重复创建 composable | 保持现有会话与连接状态在路由切换时不丢失 |
| 将项目筛选与最近会话放入首页，将连接配置放入设置页 | 提高移动端主路径效率 |
| 重写全局视觉变量和基础 UI 组件 | 当前工具面板感太重，不符合信息流移动端体验 |

## 遇到的问题
| 问题 | 解决方案 |
|-------|------------|
| 仓库处于脏工作区 | 仅在当前根目录文件上增量修改，不回滚任何现有文件 |

## 视觉/浏览器发现
- 当前界面是工具面板式排布，顶部配置卡片和双栏布局压缩到手机上后，视觉重心混乱。
- 移动端更适合会话列表首页 + 独立聊天页 + 设置页的原生聊天应用结构。
- 轻玻璃感卡片、底部 tabbar、横向项目胶囊和独立聊天页，能显著强化“手机消息流”而不是“压缩后的桌面后台”。
