# 发现与决策

## 需求
- 在项目列表里增加项目级能力入口，但不要直接开始开发。
- 能在前端直接读写项目根目录中的待办 JSON，不依赖额外接口服务。
- 能显示已授权项目目录下的文件树，并对项目内文件做简单只读预览。
- 不需要编辑和保存普通文件。
- 需要同时考虑移动端和 PC 端的交互与页面结构。

## 研究发现
- `src/pages/ProjectsView.vue` 已经是项目列表的主承载页，项目卡片已有“图标”“新建对话”等动作，适合继续承载“进入项目”的入口。
- `src/pages/DesktopWarRoomView.vue` 会在 PC 桌面模式下把 `ProjectsView` 收进左侧边栏，因此 PC 端不能简单沿用移动端全屏弹层思路。
- 当前项目页更像“项目目录清单”，而不是“项目工作台”；如果直接把待办列表和文件树塞进卡片内部，移动端会迅速失控。
- 浏览器文件系统能力天然以“用户授权目录句柄”为中心，待办读写和文件树遍历都应围绕同一个项目目录句柄建模。
- 文件树与待办共享同一目录句柄，首次授权后同时解锁两个能力，是最自然的状态模型。

## 技术决策
| 决策 | 依据 |
|----------|-----------|
| 项目卡片只保留轻量主动作，深层内容进入“项目工作台” | 让项目页保持扫描效率，不把复杂内容堆在列表页 |
| 项目工作台分成 `待办` 和 `文件` 两个一级模块 | 两者都属于项目级静态管理能力，适合共用容器和权限状态 |
| 待办按 `未完成 / 已完成` 两组组织，不做标签、优先级、备注等高级模型 | 第一版聚焦基本记录与回写 JSON，降低 UI 和数据复杂度 |
| 文件树默认忽略 `.git`、`node_modules`、`dist`、`coverage` | 避免首次打开项目时加载过重、可用性变差 |
| 文本预览与图片预览分流，二进制文件只显示元信息 | 第一版只做简单预览，不承担类 IDE 的复杂文件处理 |

## 遇到的问题
| 问题 | 解决方案 |
|-------|------------|
| 移动端与 PC 端对空间利用方式差异很大 | 拆成两套同模型不同布局：移动端全屏项目页，PC 端工作台面板 |
| 纯前端无法无感打开本地路径 | 将“首次授权目录”设计成显式第一步，并把权限状态做成 UI 主状态之一 |
| 文件树很容易把项目页做成低效的迷你 IDE | 收敛为只读、懒加载、有限预览，不做编辑和复杂资源操作 |

## 视觉/浏览器发现
- 当前项目页走卡片式列表，适合继续保持“轻摘要 + 明确动作”的视觉节奏。
- 当前 PC 桌面页已经有多面板工作区雏形，项目工作台如果能与聊天并存，会比单独跳页更符合桌面使用习惯。
- 移动端底部已有 tabbar，项目详情若再用小弹窗会显得拥挤，因此更适合独立全屏页或全屏抽屉。
