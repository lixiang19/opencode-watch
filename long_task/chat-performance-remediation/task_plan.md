## 关键问题
1. 如何让打开会话先渲染消息，再异步补齐非首屏必需数据？
2. 如何减少 SSE 高频 delta 下的数组复制、深监听和列表衍生重算？
3. 如何在不牺牲正确性的前提下，减少目录级和项目级的重复请求？

## 已做决策
| Decision | Rationale |
|----------|-----------|
| 先修复打开链路与增量更新链路 | 这两条路径直接决定手机端首屏时延和交互流畅度 |
| 保留正确性，不做模糊兜底 | 遵循仓库约束，避免以缓存掩盖真实状态错误 |
| 对列表预览改为摘要缓存而非全量消息镜像 | 列表只需要预览和状态，不需要持有整份消息树 |
| 会话打开改为“预览/缓存立即显示 + 后台补齐完整消息与选项” | 优先保证切换瞬时反馈和首屏渲染速度 |
| 只为少量高价值目录预热聊天选项 | 减少首屏和列表刷新时的目录级 5x 请求放大 |
| Git bridge 加入短时状态缓存 | 降低多面板 worktree 状态查询的子进程风暴 |
