## 关键问题
1. 单 chat 与桌面多 chat 需要共享哪些能力，哪些状态必须拆开？
2. SSE 事件如何同时驱动激活会话和桌面已打开会话，而不互相覆盖？
3. 桌面页面是否继续依赖路由拦截，还是改成显式打开会话动作？

## 已做决策
| Decision | Rationale |
|----------|-----------|
| 桌面多 chat 必须按 session 隔离运行态，而不是复用单一 `selectedSessionId` 运行态 | 目前绝大多数 bug 来自单实例状态被多个窗口共享 |
| 先保留单 chat 主路径，再为桌面端新增独立状态层 | 这样可以降低回归面，避免一次性推翻整套实现 |
