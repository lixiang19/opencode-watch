## 关键问题
1. 不引入新依赖的前提下，怎样先把最大瓶颈压下去？
2. 历史消息应该全量保留还是首屏裁剪为最近窗口？
3. 流式输出时怎样避免每个字符更新都触发整列表重滚动？

## 已做决策
| Decision | Rationale |
|----------|-----------|
| 优先做数据量裁剪和滚动策略优化 | 这是当前代码里收益最高、侵入性最低的性能改进 |
| 历史消息优先走 SDK `limit` 参数 | 比前端全量接收后再裁剪更高效 |

- 小心流式消息期间的空白气泡和滚动抖动
